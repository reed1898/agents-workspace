**TLDR** — Claude 的 Skill 功能可以帮助用户创建“菜谱”，简化重复性工作流程。

**Key Points**
- **Skill 功能**：简化了给 Claude 分配任务的过程，通过创建“菜谱”来固化工作流程。
- **SOP 卡片**：Skill 相当于给 Claude 插入一张“SOP 卡片”，即标准操作流程。
- **流程固化**：用户可以将重复性任务（如写周报、竞品调研）的流程固化下来，让 Claude 自动执行。
- **Skill 创建**：创建 Skill 需要一个名为 SKILL.md 的核心文件，并配置 YAML 中的功能描述和触发指令。
- **实操建议**：
  - **渐进式加载**：逐步添加 Skill，保持 YAML 配置精简。

  - **步骤定死**：确保每一步都有明确的指令和回滚机制。
  - **重点测试**：测试关键场景，确保 Claude 在特定指令下正确执行。

- 将具体步骤和模板放入 references/ 或 assets/ 子文件夹。

## Original Content

Claude 官方甩出来一份 33 页的 PDF，手把手教怎么给它捏 "Skills"。我看完后整理了一份精华文字版放在文末（这条是精华版的精华 没时间的话收藏这条也行吧）。

 Skill 简单粗暴点说，就是给 Claude 脑子里插张“SOP 卡片”。

以前你让它干活，得每次从头教：我要什么格式、先查哪里、避开什么坑。现在有了 Skill，你把这套流程固化下来，以后喊一句指令，它就自动按既定套路干活，特别适合写周报、做竞品调研、或者拆解需求这种重复性极高的苦差事。

文档里有个比喻挺绝：如果你用 MCP 把 Claude 连上了 Notion 或者 Linear，那叫有了“厨房”和“厨具”；但 Skill 是“菜谱”。光有厨房只能保证你能做饭，有菜谱才能保证你不炸厨房，而且每次做出来的味儿都一样稳定。

自己造一个 skill 其实也简单，本质就是一个文件夹。核心文件必须死板地命名为 SKILL .md，错一个字母都不行。

这里面最要注意的是开头那段 YAML（配置信息），你得在里面写清楚两件事：它能干嘛 + 听到哪句话就执行。写得越像人话，识别率越高。

比如（YAML 示例）：
name: sprint-planning description: 帮我搞定整个冲刺计划。当用户喊“规划这个冲刺”、“建任务”或者“排优先级”的时候，立刻触发。

最后再给几个实操建议：
1. 别一股脑全塞进去 官方希望“渐进式加载”。开头那个 YAML 越精简越好，只用来做判断。具体的步骤、又臭又长的模版、参考资料，统统扔进 references/ 或者 assets/ 子文件夹里。只有 Claude 确定要干活了，再去读那些细节。既省 Token，脑子又清爽。
2. 先写剧本，再写代码。先拿张纸，写两三个具体的“剧本”：用户吼了一嗓子（Trigger），Claude 第一步干啥、第二步干啥（Steps），最后吐出来个啥（Result）。剧本顺了，Skill 基本就成型了。
3. 别让 AI 即兴发挥 不管是“帮我搭个项目”这种目标导向的，还是“教我怎么用 Notion”这种工具导向的，最顺心意的写法只有一种：把步骤定死。 每一步都要有检查岗，还得告诉它万一搞砸了怎么回滚。你得把它当成一个只会照着 SOP 搬砖的实习生，而不是指望它突然灵光一现给你惊喜。
4. 测试别贪多 千万别一上来就搞“全覆盖测试”。找一个最棘手、最典型的场景死磕。 重点测：你说“我要干活”它得动，你说“今天天气不错”它绝对不能乱动。
