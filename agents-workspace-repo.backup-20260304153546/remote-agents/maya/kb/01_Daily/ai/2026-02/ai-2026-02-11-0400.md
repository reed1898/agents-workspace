标题：AI 日报（HN + GitHub Trending）

今日总览：
OpenAI 广告化开始实测，AI 产品商业化路径正在从“订阅”转向“订阅+广告”混合模式；同时，工程侧的“AI 代理 + 可验证测试”范式继续升温。开源端今天趋势明显偏向 Agent 工具链、结构化抽取与垂直金融研究。

HN AI 文章简报：

- 标题（含链接）：[Testing Ads in ChatGPT](https://openai.com/index/testing-ads-in-chatgpt/)（HN 讨论：[link](https://news.ycombinator.com/item?id=46949401)）
  摘要：OpenAI 开始在美国对 Free/Go 用户测试 ChatGPT 广告，Plus/Pro/企业与教育版保持无广告。官方强调“广告不影响答案”，并声明广告系统与模型回答系统隔离。广告可结合当前对话主题与历史交互做匹配，但宣称不向广告主开放聊天内容本身。
  亮点：这基本确认了“免费流量→广告变现→高端订阅分层”的产品飞轮，做 AI 应用时应提前设计广告与核心回答能力的隔离机制。

- 标题（含链接）：[Ads in ChatGPT（帮助中心 FAQ）](https://help.openai.com/en/articles/20001047-ads-in-chatgpt)（HN 讨论：[link](https://news.ycombinator.com/item?id=46968461)）
  摘要：FAQ 披露了更细规则：广告位主要在回答下方；临时会话、退出登录、图像生成后等场景暂不展示。用户可关闭个性化广告，但仍会基于当前会话上下文显示相关广告。未成年人账号（声明或预测）默认不投放。
  亮点：如果你在做对话产品，广告策略的关键不是“要不要投”，而是“在哪些高风险场景坚决不投”。

- 标题（含链接）：[GPT-5.3-Codex being routed to GPT-5.2](https://github.com/openai/codex/issues/11189)（HN 讨论：[link](https://news.ycombinator.com/item?id=46968891)）
  摘要：有用户反馈在 Codex CLI 中显式选择 gpt-5.3-codex，但日志显示实际响应模型为 gpt-5.2。问题集中在“配置显示模型”与“实际路由模型”不一致，影响可复现性与 benchmark 可信度。当前信息主要来自单个 issue 报告，尚未看到官方完整根因说明。
  亮点：信息有限，保守判断——凡是做生产级自动化，都应把“模型实际回执记录”纳入审计链，而不是只信前端配置。

- 标题（含链接）：[AI ported SimCity to TypeScript in 4 days without reading the code](https://garryslist.org/posts/ai-just-ported-simcity-in-4-days-without-reading-the-code)（HN 讨论：[link](https://news.ycombinator.com/item?id=46967968)）
  摘要：文章称开发者用 AI 代理在约 4 天内完成经典 SimCity 代码迁移，核心方法不是“盲信模型”，而是通过桥接原始实现 + 性质测试（property-based tests）反复校验行为一致性。叙事重点在“规格与验证”成为人类开发者的核心职责。文章来源为案例解读，不是正式论文。
  亮点：信息有限，保守判断——AI 编程真正可落地的分水岭在测试资产，谁先把验证体系工程化，谁先吃到 10x 杠杆。

- 标题（含链接）：[End of an era for me: no more self-hosted git](https://www.kraxel.org/blog/2026/01/thank-you-ai/)（HN 讨论：[link](https://news.ycombinator.com/item?id=46969751)）
  摘要：作者表示其长期自建 git/cgit 服务被 AI 爬虫高频请求压垮，最终放弃自托管并迁移到 GitHub/GitLab。即便 cgit 下线，爬虫仍持续打 404，导致日志快速膨胀并引发故障。事件反映了 AI 时代“抓取流量外部性”正挤压小型基础设施维护者。
  亮点：AI 应用爆发期，个人站点与小服务必须默认启用限流、缓存与日志配额，不然运维成本会被动失控。

- 标题（含链接）：[AI chatbots are no better at medical advice than a search engine](https://www.theregister.com/2026/02/09/ai_chatbots_medical_advice_sucks/)（HN 讨论：[link](https://news.ycombinator.com/item?id=46969802)）
  摘要：报道引用牛津团队与合作者研究：让普通用户在医疗场景中借助 LLM（如 GPT-4o、Llama 3、Command R+）决策，并未优于对照组（搜索引擎/个人知识），且在疾病识别上更差。论文指出真实交互中模型可能给出混杂甚至冲突建议，暴露“考试分高≠临床可用”。新闻稿转述为主，仍需结合原论文细读。
  亮点：信息有限，保守判断——医疗等高风险场景短期内更适合“AI 辅助分诊 + 人类审核”，不适合端到端替代决策。

GitHub Trending AI：

- repo：[google/langextract](https://github.com/google/langextract)

  核心亮点：把“抽取结果 + 证据定位”打包在一起，适合直接接入数据治理与审计流程。

- repo：[iOfficeAI/AionUi](https://github.com/iOfficeAI/AionUi)

  核心亮点：统一入口降低工具切换成本，适合高频 agent 协同开发场景。

今日判断：
1) AI 产品商业化进入“广告+订阅并行”的新阶段，核心竞争点将从模型能力扩展到广告治理与体验边界设计。
2) 工程实践上，AI 生成代码的护城河正在转向“规格定义 + 自动化验证”，而非纯提示词技巧。
3) 垂直 Agent（安全、金融、工作流）热度持续上行，2026 年上半年会继续出现“窄场景高价值”产品。

建议行动：
1) 你自己的 Agent/对话产品若计划变现，先做一版“广告隔离策略清单”（禁投场景、可解释开关、审计日志）。
2) 把现有 coding workflow 升级为“AI 生成 + property tests + 回归基线”三件套，优先在一个中等项目试点。
3) 从今天 Trending 里选 1 个基础能力项目（langextract 或 gh-aw）+ 1 个垂直项目（TradingAgents-CN 或 dexter）做 7 天小实验，产出可复用模板。
