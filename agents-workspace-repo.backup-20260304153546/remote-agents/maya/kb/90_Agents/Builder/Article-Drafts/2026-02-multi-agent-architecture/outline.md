# 多 Agent 架构变迁（文章大纲）

## 标题候选
- 我把 5 台设备连成多 Agent 系统后，学到的 4 条硬规则
- 从单 Agent 到多 Agent：一套可落地的异构协作架构
- 多 Agent 不是越多越好：我的架构变迁与控制论

## 一、演进路径
1. 本地 Mac 单 Agent
2. 本地 Mac + VPS 双 Agent
3. 本地 Mac（node）+ VPS（多 Agent）
4. 多设备（独立 Agent）
5. 多设备（多 Agent / 多角色）

## 二、关键问题与决策
- 通信方式：从群通信转向 Tailscale 内网直连
- 架构偏好：一台设备 = 一个独立 Agent（自治）
- 复杂度控制：机器分域，角色任务内临时化
- 知识库治理：共享库 + 写入规范 + 生命周期

## 三、方法论
1. 先分工，再扩容
2. 协议先于智能
3. 单一事实源（SSOT）
4. 可观测 + 可回滚

## 四、价值判断
- 异构设备是能力矩阵，不是负担
- 多 Agent 是组织设计问题，不是堆工具
- 从“有趣”到“有用”，靠指标闭环

## 五、下一步（可写在文末）

- 指标：节省时长、成功率、复用次数、付费转化
