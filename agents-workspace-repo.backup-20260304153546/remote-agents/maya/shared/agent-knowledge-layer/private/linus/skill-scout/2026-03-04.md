## 三、安装建议优先级

- **高优先级**
  - `agent-orchestrator`：实战验证多代理并行编排能力，收益直接。
  - `safe-memory-manager`：先补安全基线，再扩 Agent 自动化半径。

- **中优先级**
  - `oc-skill-router`：若近期有多模型成本压力，优先试点。
  - `unifai`：若本周要做交易/链上 Agent PoC，提到高优先级。

- **低优先级**
  - `gold-trading-skill`：偏特定金融场景且合规风险高，不建议默认安装。

## 四、风险提示（安全 / 维护 / 依赖）

1. **交易类技能（unifai / gold-trading-skill）**
   - 风险：资金/私钥操作、合规边界、错误执行成本高。
   - 建议：仅在隔离环境 + 小额测试；禁默认签名；必须人工确认最终交易。

2. **路由类技能（oc-skill-router）**
   - 风险：外部 API 依赖（Evolink）+ 路由黑箱，可能影响稳定性和可解释性。
   - 建议：先灰度到非关键任务；记录路由日志与失败回退策略。

3. **编排类技能（agent-orchestrator）**
   - 风险：子代理数量失控会导致成本飙升/上下文污染。
   - 建议：限制并发数、预算上限、任务 TTL。

4. **生态通用风险**
   - 风险：新技能版本迭代快（分钟级更新），维护质量参差。
   - 建议：固定版本安装、每周统一升级窗口、变更前先跑回归。

## 五、给 Reed 的一行结论

今天建议先上 **`agent-orchestrator` + `safe-memory-manager`**（高优先级），`oc-skill-router` 做灰度；交易类（`unifai` / `gold-trading-skill`）仅在隔离环境做 PoC，不进默认生产链路。
